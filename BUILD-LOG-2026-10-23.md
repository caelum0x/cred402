### 1. Casper live write path — wired and verified against the real Testnet node

`lib/casper/factory.ts`, `lib/casper/sdk_signer.ts`, `lib/casper/transport.ts`
already existed but `api/state.ts` never called them — every write
(`register_agent`/`stake`/`set_credit_score`/`deposit_liquidity`) only ever
touched the in-memory `Ledger` twin. Fixed:

- **New `lib/casper/live_bridge.ts`** — `CasperLiveBridge`, a process-wide
  singleton that mirrors the four explicit, user-triggered write actions onto
  the real, already-installed `deploys.testnet.json` contracts
  (`AgentRegistry`, `AgentCreditPool`) using the existing `CasperSdkDeploySigner`
  + `CasperRpcTransport`. Deliberately does **not** mirror the background
  economy-tick simulation (hundreds of events/sec in demo scenes) — only the
  API-triggered mutation points (`mRegisterAgent`, `mStake`, `mDeposit` in
  `api/state.ts`, the public `POST /v1/agents` route, and the fire-and-forget
  `set_credit_score` call inside `CreditAgent.underwrite`) — so a funded key
  is never spammed into rate-limiting.
- **`lib/casper/factory.ts`** extended to read `CRED402_CASPER_NODE_URL` /
  `CRED402_CASPER_SECRET_KEY_PEM` (PEM contents directly, for a one-env-var
  Render deploy) in addition to the existing `CRED402_NODE` /
  `CRED402_SECRET_KEY` (file path) pair; live mode now auto-enables once both
  are present, no separate `CRED402_CHAIN=testnet` flag needed.
- Every mirror attempt is logged in-process and exposed at
  `GET /v1/casper/live` (configured?, node reachable?, recent register/
  stake/score/deposit attempts with real deploy hashes + cspr.live links).
- **Honesty flags built in, not glossed over:** `set_credit_score` is
  `only_admin`-gated on-chain (the signer must be the ORIGINAL deployer key —
  a freshly generated operator key will always get rejected there; the
  result carries `admin_required: true` rather than hiding the failure).
  `stake`/`deposit_liquidity` are Odra `#[odra(payable)]` entry points; this
  submits the attached value as a plain `amount` U512 runtime arg (the same
  convention the sim-side `CasperTransport` abstraction already uses), but
  whether Odra's casper-backend WASM for a payable method actually reads a
  direct `StoredContractByHash` call that way (vs. requiring its own
  proxy-caller session) is **not yet verified against a funded account** —
  every payable mirror result carries `convention_verified: false` until a
  real funded deploy confirms it on cspr.live. `register_agent` has no such
  caveat (non-payable, non-admin-gated, and the exact pattern already proven
  by `scripts/casper_health.ts`).
- **`npm run casper:keygen`** — new script, generates a real ed25519 Testnet
  keypair fully offline (no network call, nothing spent), writes the PEM to
  `.secrets/casper_testnet_secret_key.pem` (gitignored), prints the account
  hash and the faucet URL. Ran it this round; the generated key is real.
- **Verified live, end-to-end, against the real node:** booted the API with
  `CRED402_SECRET_KEY` + `CRED402_CASPER_NODE_URL=https://node.testnet.casper.network/rpc`
  pointed at the freshly generated (unfunded) key. `GET /v1/casper/live`
  reported `live:true, reachable:true, chain:"casper-test"` — the transport
  genuinely reaches Casper Testnet. `POST /v1/agents` and
  `POST /v1/credit/deposit` both returned real RPC rejections
  (`Code: -32008, err: Invalid Deploy` — the real node's own validation,
  because the account has no balance yet), which is exactly the expected
  failure mode for an unfunded key and proves the signing → serialization →
  submission path is real, not mocked.
- **OWNER STEP (flagged, not blocking):** fund the generated key at
  https://testnet.cspr.live/tools/faucet (public faucet, captcha-gated,
  spends nothing). Once funded, `register_agent` calls will go fully live;
  `stake`/`deposit_liquidity` need the Odra payable convention confirmed

  ORIGINAL deployer's key, not a fresh one.

### 6. Cold-start UX + keep-warm self-ping

- **New `lib/services/keepalive.ts`** — `pingSelf()` hits this service's own
  PUBLIC URL (`https://cred402-1.onrender.com/v1/health` by default,
  overridable via `CRED402_KEEPALIVE_URL`) on a plain 10-minute
  `setInterval` (not the `AutonomousScheduler` used for keeper-sweep/
  automations — those stay opt-in; this is pure uptime hygiene, kept
  deliberately separate). Render's free-tier idle timer is ~15 minutes, so a
  ping every 10 keeps a service with real traffic from ever going idle in
  the first place — it can't wake itself up once actually asleep, but it can
  stop itself from sleeping. `shouldAutoStart()` gates this to
  `process.env.RENDER === "true"` (Render sets this automatically) or an
  explicit `CRED402_KEEPALIVE_URL`, so local dev is unaffected — verified
  `shouldAutoStart({})` is `false` and `shouldAutoStart({RENDER:"true"})` is
  `true`.
- **Frontend:** `frontend/src/api.ts` adds `fetchColdStartAware()` — retries
  a request with backoff (1.5s → 20s, ~56s total) on network failure or a
  502/503 "still booting" response, calling an `onRetry(attempt, elapsedMs)`
  callback. `x402Buy()` now takes an optional `onRetry` and
  `X402Playground.tsx` shows a visible "⟳ cold start — API was asleep,
  retrying automatically (attempt N, Ms so far)…" chip instead of a dead
  error state, plus a real error chip if all retries are exhausted.
- **SDK:** `sdk/index.ts`'s internal `get`/`post` now route through a
  `requestWithRetry` with the same backoff/502-503 handling, so a real
  Node/TS integrator's first call survives a cold Render dyno instead of
  throwing immediately. Python/Go/Rust SDKs still need the equivalent —
  **remaining**, not done this round (see below).
- No emoji; the retry chip uses `⟳`/`✗` glyphs, matching the rest of the
  console's existing symbol-only chip style.

### 15. Self-hosting quickstart — docker-compose + one-command bootstrap, both run for real

- Found an **existing but broken** `infra/Dockerfile` + `infra/docker-compose.yml`
  (production-oriented, requires `CRED402_ADMIN_API_KEY` — not a quickstart)
  and fixed a real latent bug in it while verifying: `VOLUME ["/data"]` was
  declared after `USER cred402` switched to a non-root user, but nothing
  ever `chown`'d `/data` to that user first — Docker creates a fresh named/
  bind volume owned by `root:root`, so the container crash-looped on boot
  with `EACCES: permission denied, mkdir '/data/algorand-payment-attempts'`
  the moment a volume was actually mounted (which both compose files do).
  Fixed in `infra/Dockerfile` with a `chown -R cred402:cred402 /app /data`
  before the `USER` switch — this also silently fixes `infra/docker-compose.yml`,
  which shares the same Dockerfile.
- **New root-level `docker-compose.yml`** — the actual zero-config quickstart
  (`infra/docker-compose.yml` stays as the fuller auth-required/Postgres/
  indexer production-like stack): `CRED402_AUTH_REQUIRED=false`, no other
  env required, builds from the now-fixed `infra/Dockerfile`, serves the
  console at the same origin as the API.
- **New `scripts/bootstrap.sh`** — the non-Docker one-command path: installs
  root + frontend deps if missing, starts the API, polls `/v1/health`, runs
  `scripts/seed_demo_agents.ts` against it (so the dashboard isn't empty on
  first load), starts the Vite console, prints both URLs, tails both logs
  until Ctrl+C (which cleanly kills both processes via a trap).
- **Verified both for real, not just reviewed:**
